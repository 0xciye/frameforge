# FrameForge agent notes

FrameForge is a local-first Tauri 2 desktop application for exact-center-cropped object-detection datasets, annotation, YOLO11n training/fine-tuning, benchmarking and deployment export. Extraction, manual labeling, dataset validation/grouped splits/YOLO export with negative sampling, frozen evaluation sets and lineage/replay, ONNX metadata inspection, YOLO11n training, verified-checkpoint inference with project-wide batch suggestions and candidate-negative review, trusted compatible YOLO11n checkpoint import, fixed-set model evaluation, and Champion/Challenger comparison/promotion/rollback are implemented. Checkpoint import and Champion/Challenger have fake-runtime engine coverage; no usable local checkpoint is available for real-model click-through. Deployment benchmarking/export and full-scale real-model training validation remain unavailable.

## Read first

Read `AGENTS.md`, `PRODUCT.md`, `DESIGN.md`, and `DEVELOPMENT.md`; inspect Git status before editing. Repository docs and verified code are the source of truth for phase/status.

## Architecture and safety

- UI: React, TypeScript, Tailwind CSS, native Tauri dialogs.
- Desktop boundary: allowlisted Rust commands validate inputs and start Python directly; do not invoke a shell.
- Add every module imported by `engine/frameforge_engine.py` to the Tauri resources in `src-tauri/tauri.conf.json`; verify imports and health from the built app bundle.
- Engine: Python JSON-lines on stdin/stdout, diagnostics only on stderr; OpenCV handles media, ONNX Runtime currently inspects models on CPU, SQLite stores `.ffproj` files.
- YOLO11n training uses the optional engine[train] extra (PyTorch, Ultralytics, psutil). It accepts datasets above 20,000 images and epoch settings above 300 per image size (engine limit: 10,000), runs each size independently, and leaves image caching disabled to avoid holding the full dataset in RAM. Patience 0 disables early stopping when the user wants all configured epochs. Store checkpoints/logs/config under the chosen output, cache pretrained weights in app data, and report the actual device and metrics. The 20,003-image/301-epoch queue was checked with a fake trainer for scale/config propagation; this is not a full real YOLO soak run. Fine-tuning accepts only a registered YOLO11n detection checkpoint whose SHA-256 matches and whose class schema matches the dataset; imported checkpoints require an explicit trust confirmation and managed copy.
- Never fabricate media, ONNX metadata, detections or annotation results. Manual labels must come from user edits and remain independent of inference.
- Manual labeling requires a saved `.ffproj` so annotations can autosave to SQLite. Class IDs are stable: Head = 0, Body = 1. Store and validate boxes in the original image's pixel coordinates.
- Inference must use a verified checkpoint, match the project class schema, and report pixel-space boxes and actual confidence. User-imported `.pt` files require an explicit trust warning, YOLO11n detection validation, a 2 GiB size cap and source/copy checksum checks; passive Smart Folder Discovery never loads them. Ultralytics NMS runs once; the final confidence filter is inclusive. Skip boxes within 1 px of a crop edge because the object may be clipped or larger than the crop; if all boxes are skipped, do not create a negative candidate. Save remaining AI annotations as `needs_review` with model ID and checkpoint SHA-256; preserve them during manual autosave. Acceptance or edits mark them reviewed; rejection keeps a reversible rejected record. The same checkpoint may be run again on an image after all earlier suggestions from that checkpoint were rejected.
- Project-wide inference loads the model once, predicts in bounded batches, and persists bounded SQLite chunks. Recheck each image fingerprint at the commit boundary and skip changed inputs. Cancellation preserves completed chunks. Only true zero-detection results become reviewable negative candidates with model/checkpoint provenance and a source-image fingerprint; a prediction skipped for touching the crop edge is not evidence of a negative image. Only human confirmation makes one a reviewed negative.
- Dataset export includes reviewed manual annotations, reviewed AI suggestions and confirmed negative candidates; excludes images with unreviewed manual boxes and pending/rejected AI boxes or candidates. Never treat an image with a pending candidate or suggestion as a reviewed negative. Parent replay skips unreviewed training rows and rejects fixed validation/test rows with unreviewed manual boxes. Group video/time segments and byte-identical images into the same split, preserve image pixels, and write normalized YOLO labels plus integrity/provenance into a new version directory.
- Negative sampling defaults to 10% of the final dataset, with 0/5/10/25% presets and custom 0–100%. Select deterministically from the seed and exclude near-duplicates at dHash distance ≤5; 100% keeps every eligible negative. Never drop a negative from a parent's frozen validation/test set to meet the quota; preserve it and report when the actual ratio exceeds the requested cap. Candidate-negative decisions still require human confirmation.
- Dataset lineage accepts only a valid FrameForge parent manifest. Freeze validation/test only after every image is reviewed; child versions preserve those images and labels byte-for-byte and never move their source groups into training. Historical train replay policies are `all`, `balanced`, and `new`; record parent/checksum, version, annotation revision, fixed-set IDs, image/label hashes and replay policy. Training queue and run configs inherit this lineage.
- Fixed-set model evaluation accepts only a FrameForge manifest with frozen validation/test sets and an internal registered checkpoint whose SHA-256 still matches. Recheck split membership, all image hashes, fixed-set label hashes, class schema, and cross-split image/group leakage. Persist overall/per-class metrics, exact evaluation conditions, user-defined targets and history. Blank targets stay unset; deployment latency/FPS/memory remain `not_measured` until measured on a real runtime/device.
- Champion/Challenger uses validation only; test remains the final holdout. Compare only matching fixed-set fingerprints, class schema, inference/runtime conditions, hardware and verified checkpoints. Block unmet configured targets or regression beyond the user tolerance (default 0); promotion is explicit and rollback preserves history.
- The dHash threshold is the maximum Hamming distance between 64-bit hashes, not a number of images. The default 5 filters a crop when its hash differs by at most 5 bits from a recently retained crop; the gallery reports the actual number of filtered crops.
- Project schema v4 adds AI model/checkpoint provenance, reviewable negative candidates and migration from v1/v2/v3 when writing.
- Smart Folder Discovery scans only inside the user-selected root, skips symlinks, reports bounded progress, and reads YAML/CSV metadata without loading `.pt` files. Reject external YAML references; discovered runs/checkpoints remain untrusted and must not become fine-tuning choices until a checkpoint is explicitly imported through the trust flow.
- Open the app directly into the extraction workspace. Run engine health in the background and keep its status in the toolbar; do not show a blocking welcome/check-engine screen.
- Automatically save a private local workspace snapshot and restore it after the background health check without a recovery dialog. Serialize snapshots with project writes; if the original `.ffproj` is missing or its checksum changed, restore as an unsaved project so it cannot overwrite the original silently.
- Accept video only up to FHD 1920×1080; reject larger video during import, preview, and extraction without scaling. Do not add higher-resolution video options. Preserve the source resolution of smaller video. Limit crop/output dimensions to 1920×1080; training `imgsz` is separate from input-video resolution and must not expand video support.
- Current performance evidence is a synthetic H.264 FHD batch totaling four source hours: 14,400 crops in 519 seconds with 892 MiB peak RSS. It repeats one fixture and does not establish behavior across real footage/codecs.
- Exact Center Crop previews the accepted source video frame (up to FHD) through `preview_frame`, then draws a solid orange box in that frame's pixel coordinates using `floor((frame − crop) / 2)`. Equal W/H dimensions make a square; changing a preset resizes the box over the same frame. Never replace the displayed frame with a crop output image.

## Development practice

Keep changes small and aligned with the roadmap. After each completed work turn, update `README.md`, `AGENTS.md`, `agent.md` and `DEVELOPMENT.md`; also update product/design docs and `CHANGELOG.md` when the change affects them. Report only checks that actually ran. Never claim Windows, DirectML or RX 6600 support until validated on Windows hardware; current Windows work remains pending.
